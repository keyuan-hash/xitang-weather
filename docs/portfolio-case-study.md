# 喜糖天气：从个人灵感到家人可用的天气应用

**作品定位：** 用一只真实的猫，把抽象的天气信息变成有情绪、有场景、也可靠的日常陪伴。  
**我的角色：** 项目发起、需求定义、体验与内容判断、迭代验收、上线决策。  
**协作方式：** 借助 AI 辅助场景创作、编码与测试，我持续提出标准、筛选结果、指出问题并验证成品。

## 起点：天气 App 已经很多，为什么还要做一个？

我想让家人打开天气时看到的是熟悉的喜糖，而不是一张与生活无关的天气图标。这个想法同时有两条必须满足的线：天气信息要能用，猫咪形象要像她本人。用户需要看清温度、体感、降水、风和预报；喜糖则需要随天气自然地改变状态，而不是固定照片上随手加特效。

## 我做出的关键决策

1. **先定义天气与场景的关系。** 将天气代码、天气类别、当地昼夜、场景素材和台词分开。这样下雨、雷暴、高温等情况有明确优先级，也方便日后只替换一张 `webp` 图片，而不用改页面逻辑。
2. **把“像喜糖”当成验收条件。** 初版多云、阴天重复用图，天气只是飘在照片外面。我要求重新选择参考照片，给每个天气状态设计独立的姿态、道具和光线：雨天躲在干燥处、雪天有围巾、高温四脚朝天。这一步决定了作品的辨识度。
3. **让人格来自真实生活。** 喜糖胆小、挑食、爱睡觉，喜欢虾子和罐头；左凡妈妈和寇大哥是她熟悉的人。台词系统根据天气、温度与时间变化，保留她的小脾气，也让提示语更暖心。
4. **把“能分享给家人”当作上线标准。** 早期托管链接在中国大陆手机上无法打开。我选择专属域名和腾讯云托管，处理正式环境的天气接口，再检查手机上的天气、城市搜索和预报。能够打开的真实链接，比只在开发电脑上演示更重要。

## AI 在哪里帮了忙？

| 环节 | 我的工作 | AI 辅助 |
| --- | --- | --- |
| 产品与内容 | 提出概念、确定喜糖性格、选择照片、写出需要的天气状态并审阅文案 | 扩展台词候选、协助梳理规则 |
| 视觉 | 指出照片叠背景与场景重复的问题，确定与天气结合的画面方向并逐张验收 | 基于参考照片创作天气场景插画 |
| 开发 | 给出功能与验收要求，检查手机实际使用、反馈问题和调整方向 | 生成和修改 React/TypeScript 代码、测试与部署脚本 |
| 上线 | 确定家人无需登录、中国大陆可访问的目标，选择域名与托管方式并验证 | 协助排查接口、构建与浏览器问题 |

这份作品希望体现的不是“我手写了所有代码”，而是我能把 AI 的产出纳入可检查、可改进的产品过程。出现不符合目标的结果时，我能说明哪里不对、为什么不对，以及下一版应该怎样验证。

## 最终交付与仍待完善

目前已有 [公开可体验的网站](https://xitangweather.cn/)、12 个天气场景、24 小时和 7 天预报、城市搜索与收藏、iPhone 主屏幕使用方式，以及通过的自动检查。具体证据见 [验证记录](portfolio-validation.md)。

下一步希望继续改进场景与真实照片的一致性，观察不同地区家人的实际访问情况，并在需要时迁移到原生桌面或移动壳。当前不会把 Web App 描述为已上架的 iOS 原生应用，也不会把场景插画称为实拍照片。
